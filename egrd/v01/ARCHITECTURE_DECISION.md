# Decision: gather missing mechanism evidence before a new Agent

**EGRD_RESEARCH_COMPLETE_MORE_EVIDENCE_REQUIRED**

Do not implement EGRD V0.1 production code yet. Prioritize **M2 evidence-aware next-action selection as a hypothesis**, not a demonstrated solution or an approved controller. The observed gap is between inspecting relevant code and selecting/executing a discriminating check and defensible repair. The data do not establish that static localization or retaining multiple patches is the missing capability.

The smallest executable subset is already present in MEER: source-bound check execution, stale-evidence rejection, duplicate-check suppression and bounded local execution. Adding another ledger or more decision instructions would not resolve whether Gemma invokes that mechanism, whether its assertions address the Issue, or whether it acts on contradictory results. The unchanged PR31 B/C experiment is the appropriate existing diagnostic; this task neither launches nor alters it.

Implementation GO requires evidence of an unmet operation that this subset cannot handle, together with an official deployment path. Specifically:

1. Measure real Skill invocation/bypass and check relevance under the frozen MEER protocol, with unknowns retained.
2. Independently review the proposed check/hypothesis **before revealing native outcome**, distinguishing trivial, wrong-contract and useful checks. Current autopsy labels are retrospective and outcome-visible.
3. Show at least one recurrent, actionably addressable decision failure and a concrete executable response that does not require host interception. A single plausible story is insufficient.
4. Specify cost/failure bounds and a matched inert interface control; no guard/prompt/budget co-treatment.

If Skill bypass dominates, a new optional Skill may not solve it. Global enforcement would require a verified organizer-supported interface; it cannot be implemented by changing the research Runner. If Skills are used but wrong hypotheses dominate, revisit M1 with evidence rather than adding stricter assertion accounting. If supported patches are demonstrably lost, revisit M3 with version-bound restoration.

Negative findings are part of the decision: no universal earlier-edit advantage, no token-saving guarantee, no proof of lost correct patches, no MEER real-Gemma efficacy data in this evidence set, and no causal explanation of formal score decline. Preserve S0 as best-observed formal baseline and keep all frozen candidates.
