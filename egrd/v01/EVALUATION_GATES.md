# Evaluation gates and budget assumptions

| Gate | Evidence required | Current status |
|---|---|---|
| Historical integrity | Original raw archives, candidate match, errors separated, source hashes | PASS for enumerated coverage; limitations explicit |
| Diagnosis | Actual recurring behavior and plausible addressable link to repair | PARTIAL: decision/verification gaps observed; causal bottleneck not isolated |
| Competition interface | Executable permitted component, no evaluator/Runner changes | Skill subset established for pinned environment; global controller unavailable |
| New mechanism necessity | Adds a justified operation not already tested by MEER | NOT ESTABLISHED |
| Prospective eligibility | Untouched task pool and source/alias/admission lock | NOT RUN; existing MEER reservations unchanged |
| New candidate engineering | Exact artifacts, official CPU path and mechanism tests | NOT RUN; no EGRD production candidate |
| Real-model effect | Matched native outcomes, adoption and costs | NOT RUN |
| Competitive replacement | Independent replicated gains and acceptable failures/costs | NO-GO; retain S0 |

The present task passes research reproducibility, not deployment readiness. Ten local tests cover summary parsing, assertion-syntax limitations, guard versus timeout, task-target source scope, simultaneous ADK calls, preinference exclusion, dataset privacy/annotation invariants and initialization-versus-edit timing. They are analysis tests; no claimed official Compiler/Runner or Gemma test was newly executed.

## Cost and safety of a possible M2 subset

No new runtime cost was measured because no EGRD mechanism was built. Historical MEER CPU report records two executed checks plus duplicate skip totaling0.657835s on a tiny owned fixture; that scripted fixture is not a forecast for a FastAPI tree or Gemma. Use that as historical context only, not as a validated EGRD estimate.

A transparent conditional planning bound: if a future optional helper is invoked twice and each invocation retains MEER's15s subprocess cap, check subprocess time is at most30s, or10% of a300s Agent budget. Hashing, Skill loading, model turns and native tool/executor overhead are additional; no reliable total or token estimate exists yet. Zero model calls inside deterministic code does not mean zero invocation/context overhead. A malicious/irrelevant check can still waste its entire cap. A repeated identity cache may avoid a subprocess but cannot save an already-made model request.

Before implementation GO, benchmark hash/serialization and process cleanup on actual representative workspace sizes without hidden tests, then measure real model invocation overhead. Set a prospective acceptable overhead policy and report time remaining for repair. Do not promise a fixed gain, silently exempt helper costs from300s, or impose a global submission block unsupported by the official interface.

No extra GPU/Notebook/official submission request occurred in this research. Historical UNKNOWN dispatches, timeout records, candidates and readiness states are not rewritten. New authorized GPU execution, if pursued in another task, must still satisfy its own live model/resource/conflicting-job/identity gates.
