# EGRD V0.1 research decision

**EGRD_RESEARCH_COMPLETE_MORE_EVIDENCE_REQUIRED**

The autopsy is implemented and reproducible:11 original archives,26 real-model repair sessions,784 actual tool actions, candidate/archive/member hashes and native records.25 outcomes are interpretable;13true/12false, with one additional fixture-confounded raw false preserved as null for repair analysis. Three true cases are owned synthetic repetitions; do not pool these heterogeneous cohorts into a competitive success rate.

All12 interpretable failures inspected relevant implementation. Seven attempted behavioral edits; five did not. Overall21/26 attempted such edits. The most frequently assigned event patterns are F7 budget/closure12/12 and F5 verification gaps7/12, followed by F6 selection2/12,F3 demonstrable generated defects2/12,F4 unacted-on feedback1/12. These are conservative, nonexclusive retrospective observations, not precise causal probabilities. Semantic information gain, lost-correct-patch frequency and internal causal understanding remain unknown.

First priority is to test M2's proposed link between evidence and next action, using the already frozen MEER mechanism/control experiment without modifying it. A new optional evidence ledger would duplicate existing code before its adoption or value is known. No evidence currently justifies a new global controller (not available in the pinned competitor interface) or bounded patch search as the primary fix.

Useful positive controls include GPU03's discriminating fail/edit/pass repairs, S1's actual feedback-driven local revision despite incomplete native results, and S2 native success despite a flawed local test. Three native successes lack explicit submit. These counterexamples argue against mandatory early edits, blanket local-test-pass submission gates and treating every guard event as failed repair.

Next evidence needed: real Skill adoption/bypass, whether selected checks address the Issue, whether contradiction changes subsequent actions, and matched native outcomes/costs. Conduct an outcome-blinded relevance review before approving a new operation. Future independent task identities are not yet frozen; this research is not GPU-ready.

Ten local offline audit tests pass. No new Agent, candidate package, Kaggle Notebook, model request, GPU run or formal submission was created. S0/NoEGV/Full/Action-First/EGR/MEER packages and historical experiment files remain unchanged. PR27 Batch2 stays UNKNOWN. Original untracked MEER authorization work is untouched in its separate checkout.

S0 remains the best-observed formal baseline (0.13 versus Full0.12 and EGR0.10). These scores do not establish a controlled cause of regression. Neither EGRD nor MEER should replace S0/EGR on the strength of this research or scripted CPU evidence. Architecture novelty is not the acceptance criterion; prospective Native Resolved and full costs are.
