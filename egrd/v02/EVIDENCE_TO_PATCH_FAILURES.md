# Located code is not a demonstrated repair direction

All three Agents ultimately inspect related implementation, but none produces a
production behavioral edit. The proximate terminal cause is the common guard.
The absence of an earlier edit is observable; its internal cognitive cause is
not established by a negative native outcome.

## B/C: new code, unresolved causal questions

B/C see OpenAPI security aggregation, dependency flattening, visitation/cache
identity and inherited-scope model properties. Their emitted text includes
explicit candidate explanations and counterarguments. C event 14 and B event 22
notice that a purported cross-route global visitation explanation does not
follow from per-call visited lists/new object construction. Neither executes
a source-bound graph/reproducer check to decide between those explanations.

That supports an opportunity for a **discriminating diagnostic**, not a claim
that a correct source edit was already justified. A narrow graph/identity probe
could test whether the hypothesized reuse/conditional identity actually occurs.
Its result and effect on repair are unknown. Implementing a speculative cache
change based solely on reading these properties could break runtime behavior.

Source context is costly: B/C read 750 lines each. But within-session duplicate
read overlap is 1/0 lines respectively. These were mostly new windows, not endless
identical reads. B's runtime-cache excursion is a plausible lower-value layer
detour, explicitly recognized afterward; it also supplies information ruling
out a candidate layer. Do not label every additional search as waste.

## A: reproducer validity precedes patch validity

A's first exception is caused by its own dependency API construction. The next
two print-only schemas omit expected security because the scratch graph still
does not declare the nested dependency in the normal parameter form. The model
later identifies/corrects this. Swapping route order before that correction
cannot cleanly distinguish the framework's order/cache defect from a malformed
reproducer. This is the clearest specific low-value decision in this sample.

Later variants print the expected scope metadata for the selected graphs.
They do not establish a failing contract assertion or a pre/post production
repair. The same command is run five times, but scratch contents change;
these are not five identical unchanged-check repetitions. A contains no
production edit, so there is no supported intermediate production patch to
lose, damage or select. Bounded patch selection is not justified by this case.

## Evidence levels and limits

Relevant code location: observed. Emitted repair hypotheses: observed but
unvalidated. A valid failing public reproducer of the actual corner case: not
established. Production edit/post-edit test/explicit submit: absent. Final
native false: independently observed, but not used to invent a root cause.

`DECISION_OPPORTUNITIES.json` binds each proposed alternative to exact events,
available information and uncertainty. All are diagnostic opportunities;
none is labeled a proven missed correct patch. An earlier edit is therefore
**not established as justified** for any arm. Context opportunity and causal
understanding should be studied separately rather than forcing edit deadlines.
