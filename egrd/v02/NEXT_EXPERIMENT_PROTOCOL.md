# Conditional future study; no execution authorization

Status: **NOT_EXECUTABLE_PENDING_INTERFACE_AND_PRESERVATION_EVIDENCE**.
No new production mechanism is approved or built. No Notebook/Agent/GPU is
launched by this protocol. This is a falsifiable design for the candidate
context projection mechanism **if** its missing deployment path is established.
It is not a new authorization or a claim of GPU readiness.

## Before candidate implementation

1. Obtain the approved exact tokenizer/template by their already frozen hashes;
   reproduce all 40 archived prompt counts with no model generation. Measure
   prospective projection savings using the actual rendering, not chars/4.
2. Verify an organizer-supported deployable history/compaction extension. Do
   not inject a custom callback registry or change the trusted Runner. If no
   path exists, stop this mechanism; a research-host success is insufficient.
3. Specify removable history and protected evidence before new task results:
   exact Issue once, current production patch/source identity, fresh/stale test
   labels, latest adverse observation, explicitly unresolved questions and valid
   tool-call/result pairs. Model-authored hypotheses remain untrusted. Keeping
   these fields does not prove preservation of every semantically useful detail.
4. Run deterministic CPU fixtures for source changes, old passing tests followed
   by an edit/failure, contradiction retention, tool ID pairing, cancellation,
   exception recovery, idempotence, no source/evaluator leakage and bounded CPU
   cost. No new summarizer model or semantic oracle is smuggled into this factor.

## Prospective independence

Do not reuse 14297,14459,GPU03,V02 B,V03 or EGR/MEER development cases.14297 is
excluded even though its GPU arms never ran: it is preregistered/analyzed
development material. Union the existing historical exposure/reservation/alias

independent tasks are unavailable; do not silently release reserved identities
or choose tasks by predicted repair success. Native negative baseline and clean
environment/JUnit/identity checks precede model execution.

## Outcomes and falsification

Primary: official Native Resolved, per-task paired wins/losses/ties/unknowns.
Secondary: first relevant implementation observation, explicit unvalidated versus
defensible hypothesis, actual production edits, source-bound post-edit checks,
submission, guard/deadline/tool stops, requests/tokens/time, evidence loss,
adoption if any optional interface remains, and regressions on successful arms.
Include failed/missing/cancelled costs; unknown usage stays null.

Reduced context/guard stops with unchanged native repair and greater cost does
not support repair efficacy. New wrong edits or loss of necessary adverse
evidence falsify preservation/usefulness claims. A pairwise loss on a formerly
successful control is a negative observation, not hidden or selectively rerun.
One or two positive tasks are exploratory, not statistical/generalization proof.

S0 remains the ultimate competitive reference. It is not a pure causal control
for a modified EGR mechanism because Prompt/default generation and possibly the
formal admission path differ. A later independent deployment benchmark can
compare exact S0, but cannot attribute every S0/EGRD difference to projection.
No local success fraction is converted to an expected Public Score.
