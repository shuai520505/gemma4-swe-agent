# V1 配对试验预注册：v1-prompt-pilot-01

在任何 V1 推理前固定本方案、`preregistered.json`、两个候选源文件哈希和 Notebook。V0 的原始配置、ZIP 与首轮证据由 `v0_frozen.json` 的39项哈希保护；本次不修改它们。

## 问题与实验单位

问题：仅调整通用工作流程提示词，能否改善新公开任务上的修复结果，同时控制调用和时间成本？处理变量仅为 `prompts/system.md`。模型固定指定31B v2，六工具、单 Agent、生成默认值、上下文压缩、GPU、官方依赖和验证设置一致。

实验单位是任务配对，不是工具事件。4道任务各跑V0/V1一次，共8次；预定任务为：`fastapi_15589`（请求验证）、`requests_7315`（URL规范化）、`rich_3777`（终端环境配置）、`rich_4006`（Unicode循环/算法）。来自3个仓库。只根据公开标题及元数据选择，不查看这些任务的参考Patch或测试Patch。已审计的 `fastapi_15661` 排除，不用于估计泛化。

固定种子20261015打乱任务顺序，按任务块交替V0→V1、V1→V0，避免版本与冷热顺序完全混淆。顺序完整保存在 `preregistered.json`；每次使用新Evaluator、会话、快照与验证沙箱，串行运行，共用一个模型服务以节省启动时间。缓存、采样随机性与仓库相似性仍是限制；单次重复只能作为探索性pilot，不能声称统计显著或广泛泛化。

## 共同预算

两组均使用8分钟Agent、60次计费工具、单命令120秒、Phase2测试300秒、外层每次12分钟。这是单独的公平实验profile，不修改任一候选ZIP中原有60分钟/100工具配置。历史V0单题不是同预算对照，不混入比较。8×12=96分钟，加45分钟启动和15分钟收尾，规划156分钟；Notebook平台上限3小时，仍低于官方12小时。同步操作取消并非硬实时保证。

外层超时后停止后续任务，防止取消尚未完成的同步工作污染下一次；其余单题错误落盘并继续。服务器或接口错误停止并保留失败证据。缺失、未执行或不完整结果不得算作通过，也不补跑挑选最优结果；任何重试都必须使用新run-id并单独标注。

## 预定指标与分母

- Resolution Rate：官方 `resolved=true` 数 / 每组预定4题；只在每组结果齐全时给最终率。原始resolved保留，不由本地测试替代。
- Patch有效率：非空Patch进入官方验证测试命令，且未被Patch应用阶段拒绝的次数 / 每组4题。这仅表示可应用，不表示语义正确；准备阶段失败无法确认时按未确认有效处理并单列错误。
- 测试收集失败率：有明确pytest collection错误的次数 / 每组4题；另报 / 实际启动验证命令次数的条件率及启动次数，防止未验证任务掩盖失败。
- 模型/工具调用：官方计数均值，另保留Trace工具次数；免费提交不混入计费工具数。保留prompt/completion token总量。
- 耗时：官方单题耗时均值，外层超时记录实际已耗墙钟；共同模型启动开销单列，不混入每题均值。
- 超时与执行错误：分别保留外层超时、官方error明确报告的Agent超时、验证退出124以及未知/基础设施错误。成功完成的少数任务不替代完整分母。

所有汇总均提供每任务原始记录和缺失情况。原始Verifier输出与Trace保存在账号私有Output和本地新目录，公开PR只记录摘要、哈希及控制代码。完整配对后报告V1独胜、V0独胜和逐任务差值；n=4不足以证明总体优势。

## 判定与后续

只有配对数据完整、无系统性Harness错误时，才讨论效果。V1至少净多解决1题且资源均值相对V0不增加超过25%，才作为“值得扩大样本”的初步信号；不满足则分析实际失败，不能据此直接推广或放弃整个方法。即使达到门槛，也只建议固定V1后在更多未看过的任务及重复运行上验证。测试收集失败不能用重命名目标模块或注入事后参考答案来修正评测中的Agent。

注册时状态：未执行。运行后的真实状态和结果另存 `RESULTS.md`，不得改写注册计划或覆盖原始结果。
