# EGRD V0.1 final decision

**EGRD_PARTIALLY_IMPLEMENTED / PILOT_FAILED.** The implementation is more than prompt text: actual source-bound state, executed assertion checks, stale-evidence invalidation and local acceptance decisions run through the official sandbox Skill. However, real Gemma never invoked that optional mechanism in this pilot. There is no evidence of increased Native Resolved or superiority to frozen S0, and this is not ready for a larger controlled efficacy evaluation.

1. **Previous runtime.** S0 is one declarative Gemma LlmAgent with six official tools. FullV0.1 and EGRV0.4 primarily add prompt workflow. R2 adds deadline guidance to a later nine-tool baseline; it is not the same artifact as S0. MEER is an optional executable official Skill. Prior EGRD artifacts were designs/autopsies rather than a deployed controller. The host research harness supplies non-root workspaces, supervision, HTTP tracing, independent evaluation and cleanup. Existing Context Guard is a host-side client mechanism; this pilot does not deploy that custom guard through the official ZIP. See architecture/source pins.

2. **Genuinely implemented modules.** A stores immutable-relative-to-initial-relay Issue text/hash, structured fields and provenance. B reads actual source and executes MEER checks bound to source/check hashes. C records evidence-linked hypotheses without asserting semantic truth. D enforces local structural Issue/intent links and flags outside-intent files. E computes next actions without an extra model request. F records actual patches, bounded revisions, scoped rollback, fresh checks and diff/local acceptance. G supplies helper-clock/reserve/check duration tracking; the SDK enforces the selected300s research cap. Current CPU proof:27 module/package tests, four official Compiler packages, actual Skill lifecycle and Worker/native plumbing all PASS; inherited infrastructure tests6 PASS. Untouched S0 also compiles.

3. **Advisory/observational modules.** Causal correctness, semantic relevance, evidence sufficiency, action selection and whole-Agent budget advice remain model decisions. Global tool/token/context counters are unavailable inside the Skill and stay null; external observers measure them. Runtime-error/call-relationship dedicated evidence producers and semantic best-patch ranking are not implemented. Initial Issue authenticity is unverified when copied by Gemma. Structural IDs/filenames do not establish semantics.

4. **Can it change execution?** The script genuinely executes checks and refuses its own stale/invalid operations. Its JSON can influence the same Gemma Agent's next decision. It cannot force interception of arbitrary official edit/run/submit calls. The inspected organizer path provides no competitor CallbackRegistry; naming a YAML callback does not activate it. Actual pilot B used the Skill zero times, so execution influence was not demonstrated. No prompt reminder is counted as a deployed compulsory controller.

5. **Issue-Anchored Repair.** Locally enforced traceability, source freshness and bounded intent scope; semantic Issue alignment is advisory. Original text can be relayed incorrectly and scratch state can be bypassed/forged. Global unrelated edits or direct submit remain possible. Actual final patches did not repair the Issue.

6. **Does12B work?** Exact official allowed alias `gemma-4-12b-it-qat-w4a16-ct`, mount `google/gemma-4/Other/gemma-4-12b-it-qat-w4a16-ct/2`. Nine hashes were observed on CPU and matched on actual4L4 before load. Backend served real HTTP200 responses and ordinary official tool calls. Real Skill-calling compatibility is unverified because Gemma invoked none, despite all ten tools being advertised. Model12B is not unavailable/blocked; engineering activation failed. Current official docs distinguish300s command/verifier defaults from configurable Agent time; our Agent300s is an explicit research choice.

7. **12B versus31B latency.**12B load209.261s and per-request transport latencies are observed. No31B session/load ran after stop, so comparative latency/model-size effect is UNKNOWN. Keep the intact separately selectable31B configuration; do not substitute published/historical throughput figures.

8. **Does EGRD improve12B?** Not established. Actual A0/1, B0/2 raw SDK resolved,0 validated repairs,0 explicit submits. Only one complete paired task exists. All timed out; B has zero ledger/hypothesis/intent/check state. Nine planned sessions are NOT_RUN. The pilot is public development engineering validation, not hidden Kaggle Native or canonical SWE-bench scoring. No frozen-S0 performance anchor was run; A/C are matched-interface S0-derived controls with disclosed common prompt/interface/generation differences.

9. **Main failure modes.** Optional mechanism non-invocation; repeated broad reads/searches and diagnostic work under300s; no successful finalization; Sphinx production change then rollback; diagnostic/build artifacts in fallback; CLI availability mismatch; host timeout attribution using the wrong clock; incomplete aggregate-supervisor result/cleanup adapter. Three cancelled requests lack usage. Raw specific cleanup and aggregate unknown receipts both remain visible. See PILOT_REPORT and clock diagnostic.

10. **Which mechanism contributed most?** No causal contribution can be estimated: none executed in real B sessions and there is no module ablation. CPU tests demonstrate correctness properties only. The most consequential observed bottleneck is reachability of the executable mechanism, not prompt length, token count or number of tools alone.

11. **What remains?** A competition-supported compulsory execution/interception point, if one exists; actual model use of state; reliable host deadline attribution and aggregate supervision; optional global/context telemetry only if exposed; independently confirmed causal/semantic metrics; exact frozen-S0 anchor, held-out cohort and policy ablation. Six post-freeze consistency corrections were separately CPU tested: check-driven acceptance invalidation, stale-support policy, target-to-regression progress, counterexample revision, initial-revision/staged diff and unreviewed-new-file refusal. They were not GPU-tested and are not blamed for a pilot in which no Skill ran.

12. **Next priority.** Establish an executable mechanism that is both officially deployable and demonstrably reached, before spending more GPU on repair efficacy. First CPU-test the deadline and aggregate-supervisor adapters; inspect permitted SDK integration instead of inventing callbacks or solving bypass with a longer prompt. If mandatory execution is unsupported, report that architecture boundary and evaluate the honest opt-in design as such. Then preregister a small fresh engineering pilot, followed only on success by held-out A/B with identical model/tools/prompt/budget and a one-mechanism ablation. No formal submission or larger experiment is justified now.
