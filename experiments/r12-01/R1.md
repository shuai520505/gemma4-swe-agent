# TOOL ERROR RECOVERY
- For every edit_file call, supply every required parameter from its tool schema, including the file path, old_string, and new_string. Keep each parameter as a separate correctly formed argument.
- After the first failed edit, inspect the actual error before choosing the next action.
- Missing required parameter: correct the argument structure and provide the missing parameter. Do not repeat an incomplete call.
- Old string not found or ambiguous: read the current file region, then choose an exact, unique old_string from that content before retrying.
- File not found: verify the repository-relative path and locate the existing source file before retrying. Do not create a replacement for a file whose path was mistaken.
- Never repeat an equivalent failing tool call without new evidence or a relevant correction.
- Use edit_file as the standard way to modify existing production code. Only after confirming from actual errors that the standard edit method cannot make the intended edit may you use an allowed run_command to make that same minimal production change. Keep all existing workspace, file, and test restrictions; inspect the resulting diff.
