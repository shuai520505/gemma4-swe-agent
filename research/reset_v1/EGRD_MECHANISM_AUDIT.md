## Costs and benefits

There is no real executed Skill latency/token cost sample for current EGRD: incremental cost is UNKNOWN, not zero. Shared Skill advertisement/prompt tokens can cost context even when the Skill is not called; V0.1 A/B share that interface, so their difference cannot estimate the total cost versus exact S0. Legacy V0.3.2 reported first-request B−A =678 input tokens, but this is a different Prompt architecture, not a cost estimate for V0.2. Model loading and Worker/Native runtime do not measure Skill overhead.

No repair mechanism currently qualifies as PERFORMANCE_BENEFIT_OBSERVED. A transient Sphinx edit is ordinary Gemma behavior and cannot be attributed to a Skill that was not activated. Instrumentation improving auditability is useful engineering evidence, not a Native Resolved improvement.

Known risks: optional bypass, stale or incomplete caller action logs, helper clock starting late, model-provided semantic linkage/confidence, expensive record keeping, tests that do not discriminate the defect, duplicate or contradictory source state, and infrastructure/evaluator incompatibility. Current CPU02 proves the last risk exists.
