# S1-EGV-V0.1

EGV is one prospective verification decision: **can this proposed check add
evidence relevant to the current repair hypothesis?** Validity, provenance,
novelty and consequence are links in that decision, not four controllers or a
predicted probability of repair. The implementation is a103-word addition to
the unchanged original S0 Prompt. There is no Python policy in the Agent ZIP,
extra tool, secondary Agent, forced edit deadline, scoring function or CURE.

The Agent uses already available context to check that the input reaches the
behavior, the current workspace implementation runs, and an outcome can change
the Patch/plan. Unsupported links call for the smallest useful investigation.
Inspect/assert outcomes; exit0 is insufficient. Repetition remains legitimate
after changes in code,input,environment,hypothesis or justified confidence.
Old-behavior regressions are retained. Once adequate checks are complete,
review/submit with honest limitations. These instructions do not authorize
viewing evaluator tests or skipping failures thought to be environmental.

## Evidence behind this candidate

The frozen rich_3130 pair shows invalid pipe-paragraph reproducers,an invalid
Console export,unchanged repeated pytest commands that do not discriminate a
new cwd suspicion,and genuine useful repeats after instrumentation or repair.
It also shows a real init-order counterexample followed by correction and no
explicit submit in either arm. The proposed change addresses *verification
selection*,not localization speed,context capacity or a new submission deadline.
No task name,script,reference repair,test content or expected answer enters
the added rule. Full16-action audit and evidence limitations are separate.

## What is and is not implemented

This is **Prompt-only EGV** within the official configuration. The four
considerations are expressed as a short instruction,not enforced by a
deterministic external controller. The research Python code only validates
compatibility,audits historical evidence and investigates residual failures;
it is excluded from the submission ZIP. An unchanged model can ignore or
misinterpret this rule. CPU/API pass cannot establish Gemma obedience. A new
verbal hypothesis alone can still rationalize an unchanged non-discriminating
command;the whole relevance/novelty decision must be audited in actual actions.

Source identity S1-EGV-V0.1 is external metadata;agent.yaml and eval_config.yaml
are byte-identical to Control. Same31BQATv2,oneAgent,six tools,300s/60tools,
command120s,output16384,thinking4096,seed17,omitted include_thoughts/sampling.
candidate.json registers exact member and ZIP hashes. No existing candidate,
historical STOP,Verifier,r04/r12 or result is changed.

## Falsifiable prediction and limits

On a separately selected fresh task,compared with concurrent S0,EGV should
reduce checks that fail to reach the target or repeat without a discriminating
intervention,while retaining actual post-edit/old-behavior assertions and
reacting to counterevidence. The primary endpoint stays complete native
resolved. Fewer tests with a wrong/regressing Patch is negative evidence.
Reduced repetition alone,or an earlier edit,does not establish repair benefit.

One future pair is a mechanism smoke,not an estimate of overall resolution
rate. Repeated tool calls are measurements within a run,not independent
replicates. Fixed budget,model,source,environment and evaluator are nuisance
controls;the seeded task/run-order rule prevents outcome-based selection but
does not remove all single-task stochastic or order effects.

## Cost and stopping

No required JSON,per-call score or state history is added. A103-word prompt
still has a recurring token cost and may induce extra provenance checks or
premature confidence. Added tools/time,missing regression coverage,uncorrected
counterexamples and lost submit opportunities are explicit negative endpoints.
The CPU suite checks compatibility and human-reviewed examples check intended
semantics only. No model behavior or savings is inferred from them.

Do not expand Prompt search indefinitely. If a preregistered real smoke shows
no useful mechanism signal or worse correctness/cost,retain the negative
result and stop this candidate. At most a separately justified fresh balanced
confirmation can resolve an ambiguous signal;do not stack E3/E4/CURE or tune on
the observed task. Then assess other competition-allowed mechanisms against
their own cost/compliance evidence. No LoRA or alternative architecture is
started by this decision. Future CURE contract-plan revision is distinct from
EGV evidence acquisition and requires its own demonstrated net benefit.
