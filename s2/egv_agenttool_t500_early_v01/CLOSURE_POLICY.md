# Closure policy

Main should stop new investigation when remaining resources cannot cover feedback, repair, retest and submission. The inherited60s/8-counted-tool delegation floor is a conservative unvalidated heuristic; even above it Main must allow a repair/closure reserve. It can directly verify a simple repair and submit without EGV.

Check a suspicious custom test against the actual Issue and project rules before treating failure as a production defect. CPU F uses an immutable synthetic contract and actual executed probes to distinguish invalid expectation, real production failure, probe dependency error and unverified exit0. This is controlled-ground-truth attribution, not an automatic classifier for arbitrary software.

Remove only unrelated diagnostic files Main created; preserve pre-existing files. Execute git diff --check and inspect intended changes before submit_patch. Cleanup must not consume the submission window. Check submit results and handle errors within remaining allowance. Report incomplete checks and risks. These instructions cannot guarantee real Gemma will submit; CPU plans are scripted and native fallback still exists.
